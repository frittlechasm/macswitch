CODE CHANGE EXPLAINER · APP SWITCHER

Implementation Explainer

A Java-oriented walkthrough of the native Swift/AppKit implementation added for the macOS workspace window switcher prototype.

The implementation turns an empty project into a SwiftPM macOS executable with an AppKit event loop, menu-bar UI, Accessibility permission handling, Option-Tab hotkey registration, current-workspace window discovery, overlay rendering, and release-to-activate behavior.

Verified swift build passes. Runtime note The app is a GUI event-loop process, so swift run AppSwitcher keeps the terminal attached until the app quits.

Concept Map

  • SwiftPM executable - Java equivalent: a Gradle application module with one runnable target.
  • AppKit delegate - Java equivalent: a Spring Boot application listener that wires services at startup.
  • Service objects - Java equivalent: small Spring @Service classes with constructor dependencies.
  • Carbon hotkey callback - Java equivalent: registering a listener with native OS input APIs.
  • Switcher session - Java equivalent: a stateful controller coordinating services for one request-like interaction.
  • Accessibility window inventory - Java equivalent: an adapter over an external system API returning DTOs.
  • Public workspace filter - Java equivalent: a Strategy that filters DTOs using a secondary data source.
  • AppKit overlay - Java equivalent: a custom Swing/JavaFX component doing immediate-mode drawing.

Lesson 1: Project and App Boot

Java equivalent: a Gradle application module plus a main method that starts a desktop event loop.

The project is defined as a SwiftPM executable named AppSwitcher. Runtime starts in main.swift, creates the shared NSApplication, assigns an AppDelegate, hides the Dock icon by using accessory policy, and enters the AppKit event loop.

Line-by-Line Walkthrough

let package = Package(...)

Says: create an immutable package declaration. Does: tells SwiftPM how to build the app. Why: SwiftPM gives a minimal, scriptable setup before an Xcode app bundle is needed.

.macOS(.v13)

Says: target macOS 13 or newer. Does: constrains the available SDK/runtime APIs. Why: keeps the prototype modern without chasing older macOS behavior.

.executableTarget(name: "AppSwitcher", path: "Sources/AppSwitcher")

Says: build source files under the app source directory into a runnable binary. Does: maps the package target to the Swift files. Why: matches a single-purpose application module.

let application = NSApplication.shared

Says: get the singleton AppKit application. Does: accesses the process-wide GUI runtime. Why: AppKit apps have one shared application object, similar to one JVM process-level desktop runtime.

application.setActivationPolicy(.accessory)

Says: run as an accessory app. Does: keeps the app out of the Dock while allowing menu-bar behavior. Why: an app switcher should feel like a background utility.

application.run()

Says: start the AppKit event loop. Does: blocks the terminal process while the GUI app runs. Why: desktop apps live by handling events, not by returning immediately from main.

Line-by-Line Walkthrough

let hotKeyMonitor = GlobalHotKeyMonitor { ... }

Says: create a monitor with a closure callback. Does: stores the action to run when Option-Tab fires. Why: this keeps Carbon-specific input code separate from session behavior.

sessionController.handleSwitcherShortcut()

Says: delegate the shortcut event to the session coordinator. Does: either starts the overlay or advances selection. Why: input is a trigger; session logic decides behavior.

try hotKeyMonitor.start()

Says: call a throwing method. Does: registers the native event handler and hotkey; failure enters the surrounding catch. Why: OS registration can fail, so Swift makes the error path explicit.

RegisterEventHotKey(..., &hotKeyRef)

Says: call the Carbon function and pass storage for the registered hotkey reference. Does: asks macOS to reserve Option-Tab for this process. Why: this is the public low-level API currently used for global hotkeys.

Lesson 4: Switcher Session Controller

Java equivalent: a stateful controller coordinating services for one request-like workflow.

The session controller is the behavioral center. It checks permission, snapshots raw windows, filters candidates, displays the overlay, handles navigation, and activates or cancels the session.

Before

Shortcut events had no state machine.
Overlay lifetime was undefined.
Activation was manual.

After

func handleSwitcherShortcut() {
    DispatchQueue.main.async {
        if self.overlayController.isVisible {
            self.moveSelection(by: 1)
        } else {
            self.beginSession()
        }
    }
}

private func beginSession() {
    guard permissionService.isTrusted else {
        permissionService.requestTrustPrompt()
        Diagnostics.log("Accessibility permission is required before windows can be listed")
        return
    }

    let rawCandidates = inventoryService.snapshot()
    candidates = workspaceFilter.filter(rawCandidates)
    selectedIndex = 0

    guard !candidates.isEmpty else {
        Diagnostics.log("No current-workspace window candidates found")
        return
    }

    installSessionEventMonitors()
    overlayController.show(candidates: candidates, selectedIndex: selectedIndex)
}

Line-by-Line Walkthrough

DispatchQueue.main.async { ... }

Says: schedule UI work on the main queue. Does: ensures AppKit state changes happen on the correct thread. Why: like Swing's Event Dispatch Thread, AppKit UI work belongs on the main thread.

if self.overlayController.isVisible { ... } else { ... }

Says: branch based on overlay visibility. Does: repeated Option-Tab advances selection, first Option-Tab starts a session. Why: this matches app-switcher muscle memory.

guard permissionService.isTrusted else { ... return }

Says: continue only if Accessibility is trusted. Does: exits early after prompting/logging when permission is missing. Why: avoids running OS calls that cannot succeed without permission.

let rawCandidates = inventoryService.snapshot()

Says: get raw windows from inventory. Does: asks macOS for current app/window state. Why: every switcher session should reflect current reality, not cached stale state.

candidates = workspaceFilter.filter(rawCandidates)

Says: assign the filtered current-workspace windows. Does: removes windows that are not visible or on-screen according to the public filter. Why: workspace-specific behavior belongs in a named strategy.

installSessionEventMonitors()

Says: install temporary keyboard monitors for this session. Does: wires Return, Escape, arrows, Tab, and Option release. Why: monitors should exist only while the overlay is active.

    return
}

Lesson 5: Window Discovery and Workspace Filtering

Java equivalent: an adapter returning DTOs, followed by a Strategy filter.

WindowInventoryService reads candidate windows through NSWorkspace and Accessibility. PublicWorkspaceFilter cross-checks those candidates against Core Graphics on-screen window data.

Before

No window inventory.
No current-workspace filter.
No same-app window candidates.

After

func snapshot() -> [WindowCandidate] {
    NSWorkspace.shared.runningApplications.flatMap(candidates(for:))
}

guard let windows: [AXUIElement] = appElement.copyAttribute(kAXWindowsAttribute) else {
    return []
}

return windows.enumerated().compactMap { index, window in
    candidate(for: window, app: app, index: index)
}

let options: CGWindowListOption = [.optionOnScreenOnly, .excludeDesktopElements]
guard let windowInfo = CGWindowListCopyWindowInfo(options, kCGNullWindowID) as? [[String: Any]] else {
    return []
}

Line-by-Line Walkthrough

NSWorkspace.shared.runningApplications.flatMap(candidates(for:))

Says: for every running app, get candidates and flatten the arrays. Does: converts app list into one window-candidate list. Why: same-app windows should be separate candidates, so the unit changes from app to window.

guard app.activationPolicy == .regular else { return [] }

Says: only include normal user-facing apps. Does: filters out background/accessory agents. Why: those are usually not switch targets.

guard let windows: [AXUIElement] = appElement.copyAttribute(kAXWindowsAttribute)

Says: read the app's Accessibility windows if available. Does: returns no candidates when the OS does not provide a window list. Why: Accessibility is the public API that can inspect and later focus specific windows.

windows.enumerated().compactMap { index, window in ... }

Says: iterate with index and discard nil candidate conversions. Does: maps only eligible windows into WindowCandidate. Why: many app windows are minimized, untitled, or utility windows and should disappear cleanly.

CGWindowListCopyWindowInfo(options, kCGNullWindowID)

Says: ask Core Graphics for on-screen window-server metadata. Does: produces a visible-window snapshot used by the workspace filter. Why: public macOS APIs do not provide a direct current-Space window list, so visibility is the conservative approximation.

Lesson 6: Overlay and Activation

Java equivalent: a custom Swing/JavaFX overlay component plus an OS adapter that focuses a native window.

The overlay is a borderless floating NSWindow containing a custom NSView. It draws a translucent background, app icons, titles, and a selection ring. Activation raises/focuses the selected Accessibility window and then activates the owning app as a fallback.

Before

No overlay window.
No visual candidate list.
No activation service.

After

window = NSWindow(
    contentRect: .zero,
    styleMask: [.borderless],
    backing: .buffered,
    defer: false
)

window.level = .floating
window.collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]
window.contentView = overlayView

AXUIElementPerformAction(candidate.axWindow, kAXRaiseAction as CFString)
setBooleanAttribute(kAXMainAttribute, value: true, on: candidate.axWindow)
setBooleanAttribute(kAXFocusedAttribute, value: true, on: candidate.axWindow)
app.activate(options: [.activateIgnoringOtherApps, .activateAllWindows])

Line-by-Line Walkthrough

styleMask: [.borderless]

Says: create a window with no standard title bar or controls. Does: lets the overlay look like a system switcher, not a normal app window. Why: the switcher is transient UI.

window.level = .floating

Says: put the overlay above ordinary windows. Does: makes it visible during switching. Why: a switcher hidden behind apps would be unusable.

window.collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]

Says: allow the overlay to appear across Spaces and alongside fullscreen contexts. Does: improves visibility for a workspace switcher. Why: the UI needs to appear where the user currently is.

icon.draw(in: iconRect)

Says: draw the app icon in a fixed rectangle. Does: renders the familiar visual anchor for each candidate. Why: v1 intentionally uses app icons plus titles, not thumbnails.

AXUIElementPerformAction(candidate.axWindow, kAXRaiseAction as CFString)

Says: ask Accessibility to raise the selected native window. Does: attempts exact-window activation. Why: this is what makes two Chrome windows selectable independently.

app.activate(options: [.activateIgnoringOtherApps, .activateAllWindows])

Says: bring the owning application forward. Does: provides a fallback when exact focus is imperfect. Why: some apps may resist window-level focus, but app activation is still useful.

Runtime Flow

Gotchas

  • swift run AppSwitcher stays attached to the terminal because AppKit is running its event loop.
  • NSEvent.addGlobalMonitorForEvents observes global modifier release, but does not suppress events. Full Command-Tab replacement would need different input handling.
  • The workspace filter is public-API-based and visibility-driven; it is not a private exact Space membership query.
  • The overlay currently draws only the first seven candidates, so overflow handling is still needed.
  • Accessibility permission is required before window discovery and exact activation can work.

Verification

swift build
swift run AppSwitcher

Runtime check: grant Accessibility permission if needed, hold Option, press Tab, verify the overlay shows app icons and titles, then release Option and confirm the selected window activates.
