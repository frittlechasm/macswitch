Mac Workspace Switcher Architecture

Human-readable architecture report for the native Swift/AppKit macOS workspace switcher prototype. The agent-readable companion is docs/architecture.md. Prepared for engineering review on 2026-06-09.

The system is a SwiftPM macOS executable that runs as a menu-bar accessory app, registers a persisted Switcher Shortcut, builds a current-workspace window candidate list from public macOS APIs, renders an AppKit overlay, and activates the selected window through Accessibility with an app-level fallback.

Executive Summary

Source-backed Mac Workspace Switcher is a small native macOS prototype with explicit service boundaries for permissions, shortcut preferences, hotkey input, window inventory, workspace filtering, overlay rendering, activation, and a development app-bundle wrapper for Accessibility identity testing. Gap The app has no automated tests, no signed release app bundle, and uses a public-API approximation of Space membership that still needs regression coverage over time.

System Purpose

Source-backed The README describes a native Swift/AppKit macOS workspace switcher prototype that uses public macOS APIs, Accessibility for discovery and activation, app icons plus window titles, visible non-minimized workspace filtering, and a configurable Switcher Shortcut with Option-Tab as the default (README.md:1-11).

Source-backed The domain glossary defines Mac Workspace Switcher as a keyboard-driven macOS overlay for moving focus between visible work items, and a Workspace as the active macOS Space/Desktop (CONTEXT.md:5-11).

Data Model and Storage

Source-backed The main switching data structure is WindowCandidate, which stores process id, app name, bundle id, title, frame, app icon, and the Accessibility window reference (WindowCandidate.swift:4-12). Source-backed SwitcherShortcut models the available shortcut presets, and SwitcherShortcutStore persists the selected preset in UserDefaults.

External Integrations

Source-backed The app integrates with macOS frameworks only: AppKit for app lifecycle, menu, overlay, and screens; Carbon for hotkey registration; ApplicationServices Accessibility for permission/window control; and Core Graphics for visible window-server state.

  • AXIsProcessTrusted and AXIsProcessTrustedWithOptions check/request Accessibility trust (AccessibilityPermissionService.swift:6-15).
  • RegisterEventHotKey registers the selected Switcher Shortcut (GlobalHotKeyMonitor.swift).
  • AXUIElementCopyAttributeValue reads window attributes (WindowInventoryService.swift:85-95).
  • CGWindowListCopyWindowInfo reads on-screen window-server snapshots (PublicWorkspaceFilter.swift:25-29).

Key Flow: Switch Window

  1. Source-backed Carbon emits the registered hotkey callback and invokes onPressed (GlobalHotKeyMonitor.swift:24-36).
  2. Source-backed The delegate's closure calls sessionController.handleSwitcherShortcut() with the active shortcut's modifier flags.
  3. Source-backed The session either advances selection if visible or begins a new session (SwitcherSessionController.swift:29-36).
  4. Source-backed A new session checks Accessibility permission, snapshots raw candidates, filters current-workspace candidates, resets selection, and shows the overlay (SwitcherSessionController.swift:39-58).
  5. Source-backed Releasing the configured shortcut modifier triggers the flags-changed monitor and activates the selected candidate.
  6. Source-backed Activation raises/focuses the Accessibility window and activates the owning process (WindowActivationService.swift:5-19).

Architecture Decisions

Native Swift/AppKit executable

Source-backed The project is a SwiftPM executable targeting macOS 13, with AppKit lifecycle code at runtime (Package.swift:5-18, main.swift:3-8). A development app-bundle wrapper now exists for realistic Accessibility identity testing, while signed release packaging is still not defined.

Current switcher interaction model

Source-backed Manual validation on 2026-06-28 found opening, cycling, cancellation, and activation working as expected for the prototype. The current model uses the configured Switcher Shortcut rather than Command-Tab interception.

Public-API workspace approximation

Source-backed Filtering is implemented through on-screen Core Graphics windows and screen intersection rather than private Space APIs (PublicWorkspaceFilter.swift:25-88). Manual validation on 2026-06-28 found filtering working as expected. Tradeoff: distribution-friendly and less brittle, but exact Space membership may still be imperfect across future macOS behavior changes.

Preset-based Switcher Shortcut configuration

Source-backed Shortcut selection is limited to known presets and persisted with UserDefaults. Tradeoff: simple and reliable for the prototype, but it is not yet free-form key capture.

Service-per-responsibility composition

Source-backed AppDelegate directly constructs permission, inventory, filter, activation, overlay, session, menu, and hotkey services (AppDelegate.swift:11-37). Tradeoff: simple for a prototype, but dependency injection is manual and not yet test-oriented.

Security Controls

Source-backed The app explicitly checks Accessibility trust before listing windows (SwitcherSessionController.swift:39-44) and exposes a settings path for permission management (AccessibilityPermissionService.swift:18-26). Source-backed It does not use network APIs, store secrets, or write user data in the current codebase.

Gap There is no signed/notarized release app bundle, entitlement review, hardened runtime configuration, or distribution packaging yet. That matters because the product goal includes eventual public distribution.

Gaps and Risks

Space membership is approximate

Gap The code uses visible window snapshots, titles, PID, and frame overlap as a proxy for current workspace membership (PublicWorkspaceFilter.swift:61-88). Manual validation found behavior working as expected, but severity remains medium because future macOS, fullscreen, Stage Manager, and multi-display behavior can still regress.

No automated tests

Gap The SwiftPM package defines only an executable target and no test target (Package.swift:10-18). Severity: medium, because filtering and session transitions are behavior-heavy and easy to regress.

No Command-Tab suppression

Gap Full Command-Tab-style event suppression is not implemented. Severity: low for the current prototype because the validated model uses a configured alternate Switcher Shortcut.

Shortcut capture is preset-based

Gap Settings can choose from known Switcher Shortcut presets, but there is no free-form recorder yet. Severity: low for prototype, medium if public users need arbitrary shortcuts.

Overlay shows only seven candidates

Source-backed The overlay frame and drawing logic cap visible items at seven (SwitcherOverlayController.swift:50-51, SwitcherOverlayController.swift:91-93). Gap There is no overflow affordance yet.

Recommendations

  1. Add a test target for candidate filtering, session state transitions, and activation fallback boundaries.
  2. Add free-form shortcut capture only if preset shortcuts are too limiting in manual use.
  3. Build an app-bundle packaging path with signing/notarization before public distribution.
  4. Keep Spaces, fullscreen apps, Stage Manager, multi-display setups, Chrome, Terminal, and Finder in the manual regression matrix.
  5. Add overlay overflow handling for more than seven candidates.
