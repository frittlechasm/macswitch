Mac Workspace Switcher Architecture

Human-readable architecture report for the native Swift/AppKit macOS workspace switcher prototype. The agent-readable companion is docs/architecture.md. Prepared for engineering review on 2026-06-09 and updated on 2026-08-07.

The system is a SwiftPM macOS executable that runs as a menu-bar accessory app, registers a persisted Switcher Shortcut, builds a current-workspace window candidate list from public macOS APIs, renders a SwiftUI-hosted overlay in an AppKit panel, and activates the selected window through Accessibility with an app-level fallback.

Executive Summary

Source-backed Mac Workspace Switcher is a small native macOS prototype with explicit service boundaries for permissions, shortcut preferences, hotkey input, window inventory, workspace filtering, overlay rendering, activation, and a development app-bundle wrapper for Accessibility identity testing. Gap The app has no automated tests, no signed release app bundle, and uses a public-API approximation of Space membership that still needs regression coverage over time.

System Purpose

Source-backed The README describes a native Swift/AppKit macOS workspace switcher prototype that uses public macOS APIs, Accessibility for discovery and activation, a Command-Tab-style glass overlay with large app icons and a selected-only label with inline duplicate-app window details, visible non-minimized ordinary-window filtering, and a configurable Switcher Shortcut with Option-Tab as the default (README.md:1-11).

Source-backed The domain glossary defines Mac Workspace Switcher as a keyboard-driven macOS overlay for moving focus between visible work items, and a Workspace as the active macOS Space/Desktop (CONTEXT.md:5-11).

Data Model and Storage

Source-backed The main switching data structure is WindowCandidate, which stores process id, app name, bundle id, title, frame, app icon, and the Accessibility window reference (WindowCandidate.swift:4-12). Source-backed SwitcherShortcut models the available shortcut presets, and SwitcherShortcutStore persists the selected preset in UserDefaults.

External Integrations

Source-backed The app integrates with macOS frameworks only: AppKit for app lifecycle, menu, overlay window, system glass material, and screens; SwiftUI for overlay content layout; Carbon for hotkey registration; ApplicationServices Accessibility for permission/window control; and Core Graphics for visible window-server state.

  • AXIsProcessTrusted and AXIsProcessTrustedWithOptions check/request Accessibility trust (AccessibilityPermissionService.swift:6-15).
  • RegisterEventHotKey registers the selected Switcher Shortcut (GlobalHotKeyMonitor.swift).
  • AXUIElementCopyAttributeValue reads window attributes (WindowInventoryService.swift:85-95).
  • CGWindowListCopyWindowInfo reads on-screen window-server snapshots, including window layer metadata (PublicWorkspaceFilter.swift:40-72).

Key Flow: Switch Window

  1. Source-backed Carbon emits the registered hotkey callback and invokes onPressed (GlobalHotKeyMonitor.swift:24-36).
  2. Source-backed The delegate's closure calls sessionController.handleSwitcherShortcut() with the active shortcut's modifier flags.
  3. Source-backed The session either advances selection if visible or begins a new session (SwitcherSessionController.swift:39-56).
  4. Source-backed A new session checks Accessibility permission, snapshots raw candidates, filters current-workspace candidates, resets selection, shows the overlay, and logs total, inventory, filtering, and presentation latency (SwitcherSessionController.swift:58-115).
  5. Source-backed Releasing the configured shortcut modifier selects the current candidate for activation after closing the overlay (SwitcherSessionController.swift:128-154, SwitcherSessionController.swift:209-217).
  6. Source-backed The session rechecks Accessibility trust. If permission is no longer granted, it requests the standard macOS prompt and performs no activation (SwitcherSessionController.swift:128-144).
  7. Source-backed Activation performs a bounded check of the selected Accessibility window role. A definitively stale selection performs no activation. A valid selection, or one whose validation fails for an indeterminate reason such as a transient AX error, continues through the existing activation flow with diagnostics (WindowActivationService.swift:11-76).

Architecture Decisions

Native Swift/AppKit executable

Source-backed The project is a SwiftPM executable targeting macOS 13, with AppKit lifecycle code at runtime (Package.swift:5-18, main.swift:3-8). The development app-bundle wrapper uses a stable local certificate for realistic Accessibility identity testing across rebuilds, while distribution signing and release packaging are still not defined.

Current switcher interaction model

Source-backed Manual validation on 2026-06-28 found opening, cycling, cancellation, and activation working as expected for the prototype. The current model uses the configured Switcher Shortcut rather than Command-Tab interception.

Public-API workspace approximation

Source-backed Filtering is implemented through on-screen Core Graphics windows and screen intersection rather than private Space APIs (PublicWorkspaceFilter.swift:9-124). Manual validation on 2026-06-28 found filtering working as expected. Tradeoff: distribution-friendly and less brittle, but exact Space membership may still be imperfect across future macOS behavior changes.

Layer-zero candidate eligibility

Source-backed Ordinary Core Graphics layer-zero windows remain candidates. Elevated windows are matched to the unmatched same-process candidate with the highest intersection-over-union score, then consumed and excluded. This removes browser Picture-in-Picture and other floating windows without app-specific rules or localized title matching (PublicWorkspaceFilter.swift:15-38, PublicWorkspaceFilter.swift:75-123).

Activation-time stale-window handling

Source-backed The v0.1.0 session keeps its initial candidate snapshot while visible. After the overlay closes, the activation service checks the selected AX window role with a temporary 0.25-second messaging timeout, then restores the default timeout before activation. A definitively stale element produces a privacy-safe diagnostic with its AX error and no activation attempt. Indeterminate AX failures are logged and preserve the previous activation behavior. Because the window can close after validation, the no-activation outcome is best-effort; live candidate removal is deferred (SwitcherSessionController.swift:70-79, SwitcherSessionController.swift:128-154, WindowActivationService.swift:11-76).

Session-boundary permission handling

Source-backed Accessibility trust is checked when a session begins and again after the overlay closes but before activation. If permission was removed during the session, the app requests the standard macOS prompt, logs a privacy-safe diagnostic, and performs no activation. Continuous monitoring, custom alerts, and automatic System Settings navigation are deferred. A narrow permission-change race remains after the final check (SwitcherSessionController.swift:64-68, SwitcherSessionController.swift:128-144).

Production overlay latency measurement

Source-backed Every successful overlay opening uses monotonic system uptime to log total request-to-show() return latency plus inventory, filtering, and the synchronous overlay show() call. The total also includes main-queue dispatch and session orchestration, so the stage values do not necessarily add up to it. The metric does not measure compositor latency. A dedicated default-level unified logger makes only these four numeric measurements public and queryable; general diagnostics remain private. The instrumentation is unconditional, retains no history or window content, and must remain enabled through the first production rollout. A performance target will be chosen only after rollout measurements exist (Diagnostics.swift:4-25, SwitcherSessionController.swift:39-115).

Preset-based Switcher Shortcut configuration

Source-backed Shortcut selection is limited to known presets and persisted with UserDefaults. Tradeoff: simple and reliable for the prototype, but it is not yet free-form key capture.

Service-per-responsibility composition

Source-backed AppDelegate directly constructs permission, inventory, filter, activation, overlay, session, menu, and hotkey services (AppDelegate.swift:11-37). Tradeoff: simple for a prototype, but dependency injection is manual and not yet test-oriented.

Security Controls

Source-backed The app explicitly checks Accessibility trust before listing windows and immediately before activation (SwitcherSessionController.swift:64-68, SwitcherSessionController.swift:128-144) and exposes a settings path for permission management (AccessibilityPermissionService.swift:18-26). Source-backed It does not use network APIs, store secrets, or write user data in the current codebase.

Gap There is no signed/notarized release app bundle, entitlement review, hardened runtime configuration, or distribution packaging yet. That matters because the product goal includes eventual public distribution.

Gaps and Risks

Space membership is approximate

Gap The code uses visible window snapshots, PID, window layer, and frame overlap as a proxy for current workspace membership (PublicWorkspaceFilter.swift:40-123). Manual validation found behavior working as expected, but severity remains medium because future macOS, fullscreen, Stage Manager, and multi-display behavior can still regress.

No automated tests

Gap The SwiftPM package defines only an executable target and no test target (Package.swift:10-18). Severity: medium, because filtering and session transitions are behavior-heavy and easy to regress.

No Command-Tab suppression

Gap Full Command-Tab-style event suppression is not implemented. Severity: low for the current prototype because the validated model uses a configured alternate Switcher Shortcut.

Shortcut capture is preset-based

Gap Settings can choose from known Switcher Shortcut presets, but there is no free-form recorder yet. Severity: low for prototype, medium if public users need arbitrary shortcuts.

Overlay shows only seven candidates

Source-backed The overlay frame and layout logic cap visible items at seven and keep the selection centered as the visible slice changes (SwitcherOverlayController.swift). Gap There is no overflow count or scrollbar affordance yet.

Local signing is machine-specific

Gap The self-signed development certificate exists only in the current login keychain. Other development machines must create their own identity or set CODESIGN_IDENTITY to an available Apple Development identity.

Recommendations

  1. Add a test target for candidate filtering, session state transitions, and activation fallback boundaries.
  2. Add free-form shortcut capture only if preset shortcuts are too limiting in manual use.
  3. Replace local development signing with a Developer ID or other distribution signing and notarization path before public distribution.
  4. Keep Spaces, fullscreen apps, Stage Manager, multi-display setups, Chrome and Helium Picture-in-Picture, Terminal, and Finder in the manual regression matrix.
  5. Add overlay overflow handling for more than seven candidates.
